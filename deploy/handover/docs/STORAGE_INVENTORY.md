# Файловые данные ASPM 1.0.1

Исходная точка: ветка Enterprise Monitoring на `77a6b79a2e`, проверенная сборка `a4fb9e89926f`, Helm `0.1.0-rc.10`.

| Данные | Хранилище до изменений | Запись и чтение | Жизненный цикл и права | Изменение для S3 |
|---|---|---|---|---|
| Исходные сканы | `ASPM_ARTIFACT_ROOT/originals/` на приватном томе | `accept_scan` вызывает `save_original`. Worker и benchmark повторно открывают локальный путь. API проверяет SHA-256 и размер. | ScanRun фиксирует путь и хеш. Отдельный outbox регистрируется в транзакции. Скачивание по Product, repository и scope. | Условная запись, проверка долговечности, версия объекта в PostgreSQL. Worker читает тот же проверенный буфер, что передаётся parser. |
| Generated HTML/JSON | `ASPM_ARTIFACT_ROOT/reports/`, два файла на попытку | Celery пишет оба файла в приватную директорию. API читает файл после проверки SHA-256. | UUID попытки и версия отчёта. PostgreSQL защищает завершённый отчёт. Внешняя выдача через Django attachment с CSP. | Временные файлы до публикации обоих объектов. Переход в COMPLETED вместе с фиксацией метаданных и завершением outbox. |
| Classic Reports | Синхронная выдача HTML/JSON и XLSX. XLSX использует NamedTemporaryFile. | Classic UI и API, включая Report Builder и Quick Reports. | Авторизация исходной операции, экспорт живёт в рамках HTTP-запроса. Модели для долговременного файла нет. | Общий том не требуется. Сохраняется формирование по запросу. |
| Скриншоты и вложения | `MEDIA_ROOT/uploaded_files/` через `FileUpload.file` | Django FileField и связанные формы/API. Скачивание через `protected_serve`, `access_file` и связанные API. | Разрешения Engagement, Test или Finding. Сигналы обрабатывают замену и удаление. | Django Storage использует приватный S3, а URL ведёт на авторизованный маршрут приложения. |
| Risk Acceptance proof | `MEDIA_ROOT/risk/` через `Risk_Acceptance.path` | Django FileField. API/UI читают связанный объект. | Проверка прав на Risk Acceptance, архивирование и удаление по действующим правилам. | Тот же backend и неизменяемые ключи для новых загрузок. |
| Threat model и Selenium | `MEDIA_ROOT/threat/`, `MEDIA_ROOT/selenium/`; строковые пути | `handle_uploaded_threat`, `handle_uploaded_selenium`. Threat download читает локальный путь в Engagement UI. В текущем дереве нет вызывающего кода для Selenium writer. | Права на Engagement. Возможны старые абсолютные ссылки в PostgreSQL. | Нормализация ссылки под MEDIA_ROOT и тот же S3 Storage. Миграция сохраняет ключи существующих файлов. |
| Временные файлы | Django upload handler, nginx body buffering, parser/external helpers, XLSX | Под, который выполняет запрос или задачу. | Приватные временные файлы. Удаляются после работы или вместе с подом. | Ограниченный `emptyDir`; приложение ограничивает размер загружаемых сканов и генерируемых отчётов. |
| Static | Файлы в nginx image в ASPM Helm | Image build и nginx. | CSS, JS и изображения без данных пользователей. | Отдельный Django staticfiles backend и неизменная раздача nginx. |
| Резервные копии | `backup.sh` и `restore.sh` сохраняют/восстанавливают PostgreSQL. Evidence PVC восстанавливается отдельно. | Эксплуатационные команды. | Хеш дампа и ручная проверка данных. | Единая точка восстановления требует остановки всех writers и манифеста, связывающего копию БД с проверенными файлами. |

В Helm nginx монтирует только свой ConfigMap и временный каталог. Выдача приватных файлов идёт через Django. Readiness PostgreSQL и брокера отдельна от s3/storage preflight. Метрики вместимости файловой системы относятся к filesystem-профилю.
