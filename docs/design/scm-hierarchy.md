# SCM-иерархия проекта

`Product` остаётся проектом и границей авторизации. `Product Type` сохраняет организационную группировку. `Repository` принадлежит одному проекту. `Commit` принадлежит одному репозиторию. `Engagement` может ссылаться на коммит своего проекта. `Test` и `Finding` продолжают ссылаться на существующих родителей.

Репозиторий уникален по проекту и нормализованному HTTP(S) URL. Нормализация убирает порт по умолчанию, завершающий слеш и суффикс `.git`, приводит хост к нижнему регистру и сохраняет регистр пути. Credentials, query и fragment отклоняются. Допустимы внутренние SCM-хосты, URL хранится как метаданные. Git SHA уникален в пределах репозитория. Принимаются полные SHA из 40 или 64 шестнадцатеричных символов, хранящиеся в нижнем регистре.

Коммит хранит ветку, автора, сообщение, дату и список SHA родителей. Ветка описывает одну наблюдавшуюся ссылку на коммит. Один SHA может встречаться в нескольких ветках. При миграции оставляем такие legacy `branch_tag` в Engagement. Поля `source_code_management_uri`, `commit_hash`, `branch_tag` и независимые SCM-поля Test остаются доступны прежним клиентам.

Миграции добавляют nullable-колонку, индекс для связанных строк строят конкурентно, внешний ключ добавляют с `NOT VALID` и проверяют отдельно. Бэкфилл работает по PK короткими транзакциями, переносит полные однозначные пары и сохраняет исходные поля. Включение `DD_ASPM_SCM_HIERARCHY` выполняется после применения миграций. Для обновления с несколькими версиями держите новый флаг выключенным до остановки старых процессов записи. При обратном переходе на старую схему сначала выключите флаг и сохраните новые SCM-данные, если их потребуется восстановить.

Автоматический импорт разрешает SCM-контекст в рамках выбранного Product. Reimport с явным Test проверяет согласованность родителя, репозитория и SHA. Без явного Test используется подходящий тест только в контексте запрошенного коммита. Выбор и создание Engagement идемпотентны для повторных запусков CI с тем же SHA. Записи разрешаются штатной проверкой прав на Product/Engagement до создания объектов.

Сравнение двух коммитов одного репозитория использует устойчивые ключи Finding с учётом сканера и контекста теста. `fixed` означает отсутствие ключа в сравниваемом снимке. При несовпадающем наборе сканеров или области сканирования это следует интерпретировать как разницу охвата.
