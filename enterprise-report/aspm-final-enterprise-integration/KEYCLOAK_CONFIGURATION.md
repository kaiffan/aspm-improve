# Keycloak configuration

Register a confidential OIDC client with the standard flow and PKCE S256. Register the exact HTTPS callback `https://<aspm>/sso/callback` including any application path prefix. Register the login URL as a post-logout redirect if Keycloak logout is enabled. Disable implicit and direct-access grants on this client.

Set `DD_ASPM_OIDC_ENABLED`, `DD_ASPM_OIDC_ISSUER` with the full `/realms/<realm>` issuer, `DD_ASPM_OIDC_CLIENT_ID`, `DD_ASPM_OIDC_CALLBACK_URL` and the client secret through secure runtime configuration or a Secret reference. The default client authentication is `client_secret_basic`. `client_secret_post` is supported. Set `DD_ASPM_OIDC_CA_BUNDLE` to an approved PEM trust bundle for a private CA. TLS verification is required.

`DD_ASPM_OIDC_SCOPES` is comma-separated and must include openid. Role and group claim names and three role values are configurable. The base configuration uses `aspm_roles` and `aspm_product_grants` in the ID token.

Set `DD_SITE_URL` and secure CSRF/session cookies with SameSite Lax. A trusted edge must overwrite forwarded-protocol headers. Store sessions server-side. Parameter settings are documented in the generated Helm README. The synthetic realm and its client are generated by [prepare.py](../../deploy/labs/keycloak/prepare.py). Group and provider setup follow the [Keycloak protocol mapper reference](https://www.keycloak.org/admin-api/protocol-mappers) and [server administration guide](https://www.keycloak.org/docs/latest/server_admin/index.html).
