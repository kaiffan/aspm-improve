# Воспроизведение квалификации

Для тестов нужны изолированные PostgreSQL, broker/cache, test-only пользователи и namespace с меткой `aspm-lab=true`. Используйте cert CA лаборатории, реальные корпоративные данные передаются через Secret.

1. Соберите Django и nginx из подтверждённого SHA с `deploy/labs/orbstack/build-candidate.sh`. Сохраните `git rev-parse HEAD` и идентификаторы обоих образов. Рендерите Helm в server-side strict dry run, затем выполните `helm test`. Порядок изолированного развёртывания задокументирован в репозитории.
2. Для измерений acceptance добавьте `acceptance_timing.py` в диагностический WSGI disposable image. Пробу `acceptance_probe.py` выполните в observer. Передайте в JSON stdin короткоживущий токен синтетического продукта и пароль одного пользователя. Запуски A/B используют одинаковый общий ресурс, B/C одинаковую интенсивность запросов с отличием только Django CPU limit. После измерения верните исходный обычный образ.
3. Для устойчивого rollout запустите отдельные группы HTTP и TLS с `rollout_probe.py` и прежней `http_probe.py`. Для slow-download передайте токен того же синтетического скана и `artifact_port` второго port-forward к тому же ingress. Для теста с длинным drain задайте `artifact_chunk_delay` 0.10. Соберите Ready/Serving/Terminating, события, все нефильтрованные ошибки и checksum.
4. Для восстановления сформируйте отдельный синтетический fixture `provision_webhook_smoke.py`. На время опыта удержите PostgreSQL advisory lock для `aspm.ingestion.development-environment` на 40 с. Выберите PID активного prefork child и ScanRun по `celery inspect active`. Прерывайте только выбранный child в lab. Для graceful scale-down выделите выбранный worker через pod deletion cost, подтвердите его `deletionTimestamp` и после теста верните 3 Ready.
5. PostgreSQL сэмплируйте в одной сессии через `psql \watch 0.25` и `pg_stat_activity`, фильтруя текущую БД и исключая PID сэмплера. Зафиксируйте timestamp Deployment, Job create/complete, отправки и завершения ScanRun и report. Сводку из raw формирует `checks/summarize.py`.
6. Chromium запускается через `checks/browser.cjs`. Аргументы содержат каталог для результата, приватный файл с URL, именем и паролем на трёх строках и JSON тестовых пользователей Keycloak. Храните эти файлы вне Git. Django запускайте штатным `run-unittest.sh` с полной разбивкой по модулям и свежей БД на shard.
