# Webhook event contract v1

Envelope: event_id (UUID), event_type, event_version="1", occurred_at (ISO-8601), project.id, optional repository.id, commit.sha, scan.id/status, report.id/status/version, finding.id/severity, correlation_id and attributes. Payloads omit artifact contents, full Finding descriptions, access tokens, session data and arbitrary scanner metadata. HMAC signs the exact serialized bytes. Receiver ordering is not guaranteed.

Events: scan.accepted, scan.processing, scan.completed, scan.failed; report.generated, report.failed; finding.created, finding.updated, finding.severity_changed, finding.status_changed, finding.false_positive_changed; repository.created, commit.first_seen, commit.scan_completed. webhook.test is an explicit administrative test, not a business change. commit.scan_completed means one scan on that commit completed; it does not assert complete scanner coverage or a security score.

Filters are AND across fields, OR within each field. Empty filter object matches everything. Missing attributes fail a configured filter. Allowed fields: repository_id, scanner, severity, finding_status, source, pipeline_id. Repository IDs must belong to the subscription Product. Values are exact, case-sensitive strings; repository IDs are decimal strings. Scan completion severity matches any nonzero severity count; an empty scan has no matching severity. Finding status precedence: false_positive, duplicate, out_of_scope, mitigated, active, inactive. Source is api for scan/report and live for Finding state. Pipeline filter is the exact ingestion pipeline_id. Test events bypass business filters. Unsupported attributes do not silently match.
