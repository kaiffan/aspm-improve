# Webhook security

Management requires an active superuser or explicit dojo.manage_outbound_webhooks capability. is_staff and Product viewer membership are insufficient. Requests mutate only by POST with CSRF; responses containing configuration/history/secrets use private,no-store. The generated per-subscription secret is displayed once and stored encrypted using the existing AES-GCM credential facility. The platform credential encryption key must be provisioned and backed up separately. Per-webhook rotation does not rotate the platform master key.

Endpoints require HTTPS/443 with no userinfo, query, fragment or injected header characters. DNS resolution is bounded by a four-slot resolver pool and a one-second caller deadline; all returned addresses must be public. Connections are pinned to the vetted IP while TLS verifies the original hostname/SNI. Proxies and redirects are not used. Payload size is bounded; response bodies are not read or logged. Logs store safe codes/IDs and audit actors/actions, not secrets or arbitrary consumer error text. NetworkPolicy should further restrict destination egress. Internal/private corporate consumers require a separately reviewed policy extension; they are intentionally blocked in this candidate.

Headers: X-ASPM-Event-ID, X-ASPM-Delivery-ID, X-ASPM-Timestamp and X-ASPM-Signature. Verify signature as `v1=` + hex HMAC-SHA256(secret, ascii(timestamp) + b"." + raw_request_body) using constant-time comparison. Reject timestamps outside a short tolerated clock-skew window (e.g. 300 seconds); persist event IDs for deduplication. Each replay retains the event ID and gets a fresh timestamp/signature. Do not equate a valid signature with a new business event. Rotation/revocation cannot undo an HTTP request already in flight.
