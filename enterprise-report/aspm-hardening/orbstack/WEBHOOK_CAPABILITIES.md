# Возможности вебхуков ASPM

Управление находится в **Settings → Integrations → Webhooks**. Вебхуки отправляют уведомления на HTTPS-обработчик при изменениях в ASPM. Уведомление содержит версию схемы, тип и стабильный ID события и данные, необходимые для обработки события. [Контракт событий](../WEBHOOK_EVENTS.md)

| Возможность | Как работает |
|---|---|
| Подписки на проект | В одном проекте можно создать несколько подписок. Каждая имеет собственный набор событий, endpoint, параметры доставки и signing secret. |
| События | Приём, обработка, завершение и сбой скана. Создание и сбой отчёта. Создание и изменения Finding, включая severity, статус и false positive. Создание репозитория, первое появление коммита и завершение скана для коммита. |
| Фильтры | По репозиторию, scanner type, severity, Finding status, source и CI pipeline ID. Поля соединяются через AND, значения одного поля через OR. Отсутствующий атрибут не удовлетворяет фильтру. |
| Управление | Создание и редактирование, проверка настроек без HTTP-запроса, тестовое событие, отключение и архивирование. История доступна после архивации. |
| Доставка | Outbox хранится в PostgreSQL, Celery отправляет асинхронно. Можно настроить timeout, скорость и максимум попыток. DNS/сеть и HTTP 429/5xx повторяются. Ошибки конфигурации и постоянные HTTP-отказы видны в истории. |
| История и replay | Состояния pending, in flight, retry, succeeded, dead и cancelled. Для каждой попытки записываются время, HTTP-статус или безопасный код ошибки. Ручной replay сохраняет ID события и предыдущие попытки. |
| Подпись и доступ | HMAC-SHA256, заголовок времени, отдельный секрет с одноразовым показом и ротацией. Управление доступно суперпользователю или пользователю с `dojo.manage_outbound_webhooks`. Доступ на просмотр проекта этого права не даёт. |
| Ограничения сети | Публичный HTTPS на 443 с проверкой всех DNS-адресов, фиксацией IP и проверкой TLS hostname. Private, loopback и служебные диапазоны отклоняются. Redirects не выполняются. |

**Примеры использования**

- CI или SIEM получает `scan.completed` только для указанного репозитория, scanner type и уровня `High` или `Critical`.
- Отдельная подписка получает `scan.failed` для проекта независимо от severity, которого у неудавшегося скана может не быть.
- Получатель проверяет HMAC над `timestamp + "." + raw_body`, ограничивает допустимый возраст запроса и дедуплицирует `X-ASPM-Event-ID`. Доставка рассчитана на семантику at-least-once. [Заголовки и пример проверки](../WEBHOOK_SECURITY.md)
