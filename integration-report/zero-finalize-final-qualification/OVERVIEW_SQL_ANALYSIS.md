# Откуда появились десять SQL-запросов Overview

Сняты фактический SQL, параметры, места вызова и EXPLAIN (ANALYZE, BUFFERS, SETTINGS) на синтетических данных. Во всех вариантах измерялась одна авторизованная страница evidence. Сеансовые ключи в трассах удалены.

| Добавка B0 к A | Запросов | Причина |
|---|---:|---|
| Live selection | +6 | Список pipeline contexts, проверка выбранного context, конфликт job в scanner/scope/attempt, последний запуск, последний успешный запуск, точный legacy ScanSet для coverage |
| CWE/CVE | +1 | Проекция 20 выбранных immutable observations |
| Polling revision | +2 | Группировки ScanRun и GeneratedReport по статусам |
| Export authorization | +1 | Product edit для кнопки экспорта на другой вкладке |

В обоих вариантах исходные 13 запросов включали два COUNT для пагинации, группировку ScanRun для статусов Overview, сессию, пользователя, настройки, профиль, продуктовый RBAC и глобальный шаблон. Commit, Repository и Product загружаются одним JOIN с проверкой доступа. N+1 не обнаружено.

Коммит 25da29aaff устраняет пять запросов типичного Overview. Два COUNT выполняются только для открытой вкладки, проверка Product edit только на вкладке отчёта, результат группировки статусов используется счётчиками и polling revision. Pipeline из загруженного списка проверяется без SQL. При достижении лимита 101 сервер отдельным запросом проверяет явно указанный pipeline за пределами меню.

Итог 13 → 23 → 18 для обычного Overview. Пять оставшихся дополнительных запросов обслуживают отображаемые данные и polling. Последний запуск и последний успешный запуск сохраняют разные правила выбора и разные порядки.
