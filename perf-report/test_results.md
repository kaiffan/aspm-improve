# Regression tests

Тесты запущены через `run-unittest.sh` в отдельном Compose-проекте с PostgreSQL и тестовой БД `test_dd_api_check`. В итоговой сборке 43 теста прошли, 5 пропущены штатно, ошибок и падений нет. Все пять пропусков относятся к проверкам конфигурационной авторизации, которая не используется в этом режиме OSS.

| Проверка | Результат |
| --- | --- |
| Воспроизведение до патча | При росте с одного до пяти продуктов число запросов выросло с 11 до 15. Для страницы из двух продуктов было четыре SQL-запроса к findings вместо одного. Оба новых performance-assertion падали на исходном образе. |
| Products list | Постоянное число запросов, один запрос к findings на непустую страницу, точный count продуктов, порядок ID, пустой продукт, исключение неактивных findings, следующая страница и сохранение detail. |
| Products access | Ограниченный пользователь с одним доступным продуктом получил только его, даже когда в фильтре указаны доступный и чужой product ID. |
| Products delete preview | Расширенный прогон поймал, что общий пагинатор получает словари из `delete_preview`. После ограничения оптимизации действием `list` существующий `ProductTest.test_delete_preview` прошёл. |
| Findings access и FAST | Два продукта, ограниченный пользователь, offset 5 000, активные/неактивные findings, ascending ID и нестандартная для FAST сортировка `-id`. Проверены точные counts, порядок, фильтры, совпадение содержимого страницы, отсутствие чужих findings и 404 на чужой detail. SQL подтверждает двухэтапный путь при сортировке по возрастанию и fallback при сортировке по убыванию. |
| Vulnerability references | Две записи в `FindingVulnerabilityReference` с CVE/GHSA созданы в обратном порядке. List и detail сохранили порядок ссылок и JSON-структуру, на страницу приходится один запрос к ссылкам. Проверены ветки Locations и legacy Endpoints. Также прошли существующие тесты seam и PATCH для vulnerability IDs. |
| Соседние GET и схема | Прошли тесты фильтров и сортировок findings, постоянного числа SQL-запросов tests, Product API и Product permissions. `manage.py check`, `makemigrations --check --dry-run`, `spectacular --fail-on-warn`, Ruff 0.16.10 и `git diff --check` завершились успешно. SHA-256 сгенерированной схемы совпал у обеих сборок. |
| Рабочая БД и логи | В рабочей БД осталось 1 000 000 findings. В ней нет активного пользователя без staff-прав и findings с несколькими vulnerability references, поэтому эти проверки использовали отдельную БД. В логах проверенных uWSGI и A/B nginx не обнаружено traceback или API 5xx. Docker не зарегистрировал OOM или рестарты контейнеров во время прогона. |

[Release-only проверки](release_checks.py) воспроизводят совместимость двух существующих оптимизаций на версии 3.5.100. Файл можно разместить в `unittests/test_local_release_performance_checks.py` в тестовом контейнере этой версии и запустить штатным wrapper. Постоянные тесты нового патча включены в [product-findings.patch](product-findings.patch).

Нагрузочная проверка покрывает concurrency 1 и 5 и read-only сценарии. Проверка конкурентных записей для FAST и измерения при concurrency 10–25 остаются за пределами этого прогона.
