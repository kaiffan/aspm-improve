# Производительность

Финальный малый одиночный HTTP-сценарий измерил scan acceptance для 6 fixtures. Наблюдение — 190–582 мс, медиана 328.5 мс. Компьютер одновременно выполнял регрессию и лабораторные операции. Просмотр результатов API и сравнение checkout не образуют контролируемое A/B.

Короткая серия из 5 клиентов и трёх GET-маршрутов на малом dataset. 545 HTTP-запросов, 21.7 RPS, p95 613 мс, p99 1394 мс, ошибок 0. Первый запуск при пяти клиентах дал 344 запроса, 13,7 RPS, p95 921 мс, p99 1 599 мс и ноль ошибок. Вторая серия включила 10 срезов Docker stats. Максимум uWSGI составил 95,48% CPU и 196,30 MiB памяти, worker 4,53% и 20,00 MiB, PostgreSQL 68,23% и 18,39 MiB. В PostgreSQL наблюдалось до четырёх соединений вместе с наблюдателем. Worker throughput в насыщении, очередь, peak RSS, PostgreSQL WAL/locks, S3 latency и overhead мониторинга отдельно не измерены. Core9/Acceptance на 1M не запускали. Воспроизводимые планы и fixtures находятся в deploy/handover/qualification/benchmark.
